# Negotiation QA Rubric（/100）

> 打分前先跑真实性与筹码审计（话术卡逐条回溯 Brief：每个主张可定位；市场数字全部带三选一标注；〔待核〕未变实数；无虚构筹码）；审计不过直接 fatal，不进入打分。
> **QA Only 无独立 Brief 时**：审计降级为「内部一致性 + 可疑筹码」审查（抓自相矛盾 / 无依据数字 / 疑似虚张声势的筹码主张），无法核验的主张标「存疑」并要求补依据，不当作通过；同时把 BATNA Gate 双问作为诊断的一部分补问，依赖 Brief 才能判的项标注「缺 Brief · 无法完整评分」。
> 每处扣分必须引用话术卡原句（QA Only 模式下「卡面原句」= 用户粘贴的原文原句）。
>
> **分数是方向性诊断，不是校准过的精确门槛**（系列共识，沿 report-writer 实证：同稿跨模型可差数十分）。以「有无 fatal」+「方向（Pass / Revise）」为主判据，不要把 1-2 分差当质量裁决。参考方向：无 fatal 且六维明显扎实（约 ≥85）＝Pass；无 fatal 但一两维明显弱＝Borderline（修最弱维后复查）；任一 fatal 或整体明显弱＝Revise。硬停 2 轮。
> **rubric 与 mock 是两类反馈源**：rubric 抓「纸面完整度」，mock 抓「临场强度」。rubric 高分不豁免 mock；mock 打穿的洞回来修卡后只复查受影响维度，不整卷重打。

## 六维评分

### 1. 目标三层与底线 /20

- 18-20：理想 / 满意 / 底线三层齐且每层有依据（市场数据、生活成本、对内公平参照）；底线可执行（触线动作明确：接受 walk 还是转谈其他议题）；三层数字关系合理（理想不是漫天要价，底线不是「再看吧」）。
- 12-17：三层有但依据薄（拍脑袋数字）；或底线写了但没有触线动作。
- <12：只有一个「想要的数」；或底线缺失 / 含糊到无法判定何时该走（同时触发 fatal #1）。

### 2. 对方视角完整度 /20

- 18-20：对方的目标 / 约束 / 可让空间 / 可能招数四列齐且具体到「这一个对手」（这家公司的预算周期、这位老板的汇报压力），不是通用 HR 画像；至少预判 3 个高概率招数且各有应对卡。
- 12-17：有对方视角但停在通用层（「HR 会压价」）；招数预判少于 3 个。
- <12：通篇单方面陈述自己要什么，对方列空白——独白不是计划。

### 3. 让步阶梯与交换 /20

- 18-20：阶梯每步「让什么 + 换什么」成对出现（降 base 换签字费 / 接受原薪换 6 个月调薪 review）；步幅递减；可交换议题清单实际用上（≥2 个非 base 议题进入阶梯）；底线之下无台阶。
- 12-17：有阶梯但存在白让（只降不换）；或议题面窄（只有 base 和一个陪衬）。
- <12：无阶梯，只有「不行就算了」；或阶梯首步即穿底线（同时触发 fatal #6）。

### 4. 开场与锚定 /15

- 13-15：先报 / 后报分支判断有记录且理由成立（依据信息掌握度，见 brief-guide.md）；锚定数字精确非整（有依据陈述配套）；开场 30 秒完成关系锚定 + 谈话框架，不绕场外话超过两句。
- 8-12：分支判断对但锚定执行弱（整数报价无依据陈述 / 开场直接跳数字显得突兀）。
- <8：未做分支判断（默认背了一套「先报 / 后报」通用教条）；或开场卡缺失。

### 5. 异议应对覆盖度 /15

- 13-15：Brief 预判的招数每个有应对卡（对方说 X → 你答 Y → 底层逻辑一句）；场景 top 压力招（见 scenario-guide.md 各场景表）全覆盖；应对是「回应 + 转向」不是硬顶。
- 8-12：主要招数有覆盖但个别应对是空转（「我理解，但是我坚持」——没有转向路径）。
- <8：应对卡少于 3 张，或全是复述立场。

### 6. 语气与关系 /10

- 9-10：坚定而不对抗（立场硬、措辞软）；无威胁式句式；对持续关系有显式照顾（谈完还要共事的表述在场）；**按场景分判**——拒绝/婉拒场景：缓冲 → 理由 → 替代结构完整；坏消息场景：第一句直陈坏消息本身、一次说全、有处置方案（缓冲结构在坏消息场景**不加分反扣分**，见 scenario-guide #5）。
- 6-8：整体可，个别句子火药味（反问句连用 / 「你们这样不合理」类指控式表述）。
- <6：通篇对抗腔或哀求腔（两者都是筹码流失）；拒绝场景无缓冲硬砸；坏消息场景绕场入题 / 分期披露 / 裸报无处置方案。

## Fatal issues（一票 Revise）

> 每条按标注场景判定，别跨场景误用（#2 的 package 检查在拒绝 / 坏消息场景不适用）。

1. 无底线红线进入谈判（Brief 底线空 / 含糊），或话术卡出现与底线矛盾的让步
2. **〔仅谈薪 / 加薪场景〕** 单点谈判：卡面只谈 base，可交换议题清单未探索（连「不能动 base 时谈什么」的预案都没有）。**刚性带宽豁免**：用户在 Brief 标注体制内 / 国企 / 刚性职级带宽公司 → 免除签字费/期权/绩效浮动类资金议题的硬性要求，改为要求卡面至少含 2 项**非金钱组织资产**交换预案（定级复议窗口 / 核心项目署名或主导 / 提前 review 书面约定 / 培训与借调资源）——两项都没有仍判 fatal
3. 编造市场数据（〔待核〕槽位被填成实数、卡面出现 Brief 之外的市场数字）
4. 虚构筹码（假 competing offer / 编造的 deadline / 无 runway 支撑的裸辞宣言当威胁用）
5. 威胁式或情绪化升级措辞——**按措辞本身判定，不因筹码真实而豁免**（「爱要不要」「别糊弄我」类对抗腔即便 BATNA 扎实照判 fatal）；无真实 BATNA 支撑的最后通牒（「不加薪我就走」而 Brief 里是「其实走不了」）同属此条。判别边界：有真实支撑且留关系余地的底线陈述（「如果都没有空间，我可能只能遗憾选另一边」）不是威胁
6. 话术卡与 Brief 冲突（阶梯外的让步、三层目标外的数字、对方视角表没预判过的即兴承诺）

**Near-fatal（触发 Revise，除非用户显式接受风险）**：

- Fast Loop 模式下 mock 被跳过且场景是 offer 谈薪 / 在职加薪（高价值场景裸奔上场）——在 Ship Check 里必须显式标注「未经 mock 压测」。

**Fatal 的用户坚持分级**（与 SKILL.md QA Loop 同步）：#3 编造数据 / #4 虚构筹码 / #5 威胁措辞为**不可覆盖**——用户坚持也不写，拒该元素给安全替代；#1/#2/#6 类策略选择为**可风险接受**——解释风险后用户拍板则放行，scorecard 记「user confirmed」+ Ship Check 列明风险。

## 场景适配注记（非谈薪场景打分时按此重释维度）

六维骨架不变，非谈薪场景按下表重释含义打分；fatal #2 不适用于非谈薪场景：

| 维度 | 拒绝/婉拒 | 提离职 | 坏消息传达 |
|---|---|---|---|
| 目标三层与底线 | 边界清晰度（拒什么/可让什么/红线） | 决定清晰度（走的条件是否明确不留误读） | 事实完整度（一次说全无保留） |
| 对方视角完整度 | 同原义 | 同原义（挽留/交接压力预判） | 同原义（追责/扩大化预判） |
| 让步阶梯与交换 | 替代方案质量（真实选项而非空拒） | 交接方案完备度 | 处置方案完备度 |
| 开场与锚定 | 缓冲结构（缓冲→理由→替代） | 决定直陈开场 | 第一句直陈坏消息 |
| 异议应对覆盖度 | 软磨/情绪施压应对 | 挽留/counteroffer/交接绑架应对 | 追责/时点质疑/扩大化应对 |
| 语气与关系 | 同原义 | 同原义 | 同原义 + 决策请求明确 |

## 修订规则要求

坏例：「加强对方视角」。
好例：「异议应对卡第 2 张『预算有限』的回应改为绑定 Brief 对方视角表 C2（Q3 是他们的招聘冲刺季、这个岗位已空缺 2 个月）：『我理解预算有约束——如果 base 确实动不了，把到岗时间提前到下月初对团队的价值，能不能换成一次性签字费或 6 个月后的调薪 review？』」
