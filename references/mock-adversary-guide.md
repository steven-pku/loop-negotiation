# Mock Adversary Guide（谈判对抗陪练）

> 全环里 rubric 达标后的必跑环节（≥1 轮）：rubric 抓纸面完整度，mock 抓临场强度。这是排练不是加赛——mock 本身不计入 QA 修订轮数。
> 排练提升临场表现是谈判训练行业的标准做法（practitioner consensus，见 evidence-notes.md）。

## 扮演硬约束（先于一切 persona 细则）

**危机中止例外（先于本节一切强度规则）**：mock 任一回合中用户暴露急性心理危机或自伤/伤人风险 → 立即出戏，中止本轮 mock 与全部评分，按 SKILL.md「Crisis stop overrides everything」先处理当下安全，不做任何「先打完这回合」的缓冲。用户处于持续被霸凌情境（无即时风险）→ 不上高压对抗排练，改低对抗配置并向用户说明原因。对抗强度永远让位于危机中止规则。

**按 persona 利益最大化出招，不留情面。** mock 的目的是打穿话术卡，不是配合用户达成共识——不因用户处境艰难而手软，不递台阶，不主动让步。每回合出招前自问一次：「这个 persona 在这个利益下最狠的一招是什么？」出那招。偏软的 mock 是橡皮图章，排练价值归零（AI 陪练的已知失败模式，本条就是防它的）。狠在招数，不搞人身攻击——出招仍在职场对话的现实范围内。

**Mock 开始前先输出 Persona State**（三行，锁定信息边界）：
- 已知事实：（该 persona 从 Brief 对方视角表中真实掌握的）
- 禁用事实：（Brief 里用户侧/其他角色侧的信息，本 persona 无从知晓）
- 可推测但不可断言：（该 persona 按常理能猜、但不能说破的）

## Persona 库（扮演纪律：只用该角色真实会有的信息与动机）

| Persona | 他知道什么 | 他要什么 | 他能给什么 | 他不知道什么 |
|---|---|---|---|---|
| **HR / 招聘** | 岗位预算区间、职级带宽、候选人对比、招聘 KPI 与时间压力 | 在预算内快速关单、不破坏内部薪酬公平 | 区间内数字、签字费、入职时间弹性；**通常给不了**职级破格、期权特批 | 业务细节、团队真实缺人程度（只知道紧急度标签） |
| **直属老板** | 你的真实表现、团队预算、他自己的汇报压力、谁可替代你 | 留住产出、不开先例引发连锁加薪、向上好交代 | 调薪名额争取、职责与项目调整、review 承诺；**通常给不了**当场定数 | HR 侧的带宽细节、其他部门的对标 |
| **隔级 / 更高层** | 组织盘子、编制与预算大局 | 公平性、不被细节绑架 | 原则性支持或否决 | 你的日常细节（他只看结果标签） |
| **猎头** | 客户预算上限（可能比告诉你的高）、他的佣金结构（与你的 package 正相关但与「关单」更相关） | 快速关单 | 信息中介、替你传话议价 | 客户内部真实决策链 |

**信息纪律**：HR 不会说出老板才知道的事（「其实团队离了你转不动」）；老板不会引用 HR 带宽表。mock 中对手每句话前自检一次信息来源，越权信息出现即本轮作废重跑。

## 压力招数库（对手弹药）

| 招数 | 典型台词 | 攻击目标 |
|---|---|---|
| 压价 | 「预算就这些，没办法」 | 阶梯厚度：看你是否只会降 base |
| 区间取底 | 「你说 25-30，那我们按 25 定」 | 精确数纪律 |
| 拖延 | 「这个我要请示一下，下周再说」 | 时间约束：看谁更急 |
| 画饼 | 「先按这个进来，以后有的是机会」 | 收尾卡：口头承诺是否要求落字 |
| 情绪施压 | 「你这样谈显得没诚意」 | 语气与关系维：看你会不会慌着让步或炸 |
| 比价 | 「跟你同级的都没这么高」 | 依据陈述：你的锚有没有据 |
| 权限甩锅 | 「我做不了主，公司制度就这样」 | 对方视角表：真实决策链预判 |
| 反问底牌 | 「你现在的薪资是多少？」「你还面了哪家？」 | 筹码陈述：弱 BATNA 会不会被诈出来 / 会不会顺势编假 offer |
| **索证压力** | 「方便把另一家 offer 或你的薪资流水发我确认一下吗？」 | 真实性 + 隐私边界：虚构筹码当场穿帮；真实筹码考验「不撒谎、不伪造、不泄露非必要信息」的转向能力（应对分层见 cn-workplace-notes 流水条目） |
| 最后通牒 | 「明天不答复就给下一位了」 | 底线与触线动作：deadline 真伪判断 |

## 轮次协议

1. **选靶**：默认攻 QA scorecard 标记的最弱两维 + 该场景 top 压力招（scenario-guide.md 各场景表）。
2. **对打**：每个靶点 3-5 个回合。用户亲自应答（默认，训练价值最高），或用户指定「自动对打」由 Claude 按话术卡应答——自动对打时严格照卡，卡上没有的不即兴发挥（暴露卡的覆盖缺口正是目的）。**自动对打硬约束**：生成对手台词时不得参考话术卡内容——对手只凭 Persona State 的已知事实出招，卡上写了什么你不偷看（同一模型持双方上下文时，这是防信息泄露的唯一屏障）。
3. **升级检查**：每轮结束扫一遍应答有没有滑进 fatal 区（被诈出假 offer、被激出威胁句、被拖延带着穿了底线）。
4. **多轮纪律**：用户要求再来 → 新一轮只打上轮存活的洞 + 换一个未用过的招数，不重复碾同一处。**收敛信号**：连续两轮无新漏洞 → 主动建议进 Ship Check，mock 退出（无限轮陪练是拖延，不是准备）。

## Mock Findings 输出格式

```markdown
## Mock Findings（第 N 轮 · persona：HR）

### 漏洞清单
1. 【锚定卡】对方问「你现在薪资多少」，卡上无应对 → 现场应答暴露了当前薪资，锚定点位随即被参照压低（对话原文：…）
2. 【阶梯】「预算就这些」两连击后，第二次应答直接跳到了底线数字——阶梯中段台阶没用上

### 补丁建议
1. 新增异议应对卡：当前薪资问题 → 「我更希望按这个岗位的价值来谈——我的期望是 X，这个数是照同岗位数据算的」（转向不撒谎；绝不虚报当前薪资）
2. 阶梯第 2 步补执行台词：「base 动不了的话，签字费或者半年 review，哪个你这边能做主？」

### 升级检查
- 无 fatal 滑落 / 【警示】第 3 回合应答出现「那我只能考虑别家了」——Brief 中 pipeline 仅二面阶段，此句接近虚张筹码，改为「我需要几天把手上的流程走完再答复你」

### 信息越权检查
- 本轮对手台词是否全部可溯 Persona State 已知事实：✅ / ❌（列出越权句 + 其真实信息来源；出现越权 = 本轮作废重跑）
```

补丁回流修卡后，只复查受影响的 rubric 维度。
