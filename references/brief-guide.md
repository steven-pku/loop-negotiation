# Negotiation Brief Guide

> Brief 是全环的事实源：话术卡只引用 Brief 里有的东西，mock 对手只用 Brief 里对应 persona 该知道的信息。schema 见 SKILL.md「Required Brief」/ `assets/negotiation-brief-template.md`。

## 补槽追问（≤5 问，按筹码影响排序）

1. BATNA 细节（另一个 offer 的具体数字和 deadline / 现岗真实可留度）——影响一切
2. 对方约束（预算周期？岗位空了多久？他上面还有谁要点头？）——决定招数预判
3. 市场数据（你有什么可信数字？来源？）——决定锚定强度
4. 可交换议题（base 之外你在乎什么、他们可能给什么？）——决定阶梯厚度
5. 时间与关系（谁更急？谈完还要共事吗？）——决定语气档位

## 先报 / 后报分支表

> 学术侧：先报价有强锚定效应（Galinsky & Mussweiler 2001，first offer 与成交价相关 r≈.85）。中文实战侧共识却是「让 HR 先报探底」。两者不矛盾——分歧变量是**信息掌握度**。信息不对称大时先报会反噬（对方比你清楚行情，你的锚只暴露你的无知）。按下表判，把判定和理由记入 Brief。

| 你的信息状态 | 建议 | 执行要点 |
|---|---|---|
| 有可信市场数据（同司同级实数 / 可靠公开来源），对区间有把握 | **先报，精确锚** | 报精确非整数字 + 一句依据陈述；锚在理想层，留让步空间 |
| 信息不对称大（新行业 / 新城市 / 职级体系不明） | **后报，探底** | 「我更想先了解这个岗位的薪资结构和范围」反问；对方报后再用精确数反锚 |
| 对方已先问「期望薪资」（中文招聘流程默认动作，多数人躲不掉） | **缓冲后择一** | 缓冲句（「这个得看整体 package——方便先说说贵司这个岗位的范围吗」）尝试反转；对方坚持 → 回到上两行按信息状态执行，别在毫无准备时被迫吐一个随口数 |
| **对方已报价**（offer 谈薪最常见入场态：HR 数字已出） | **反锚（counter-anchor）** | 不当场接受也不硬顶原锚：① 先拆 package 口径（base / 浮动 / 福利分列，原锚常靠总包做大）② 用精确数反锚 + 一句依据陈述，反锚点位放理想层（锚定效应对 counter 同样成立，Galinsky & Mussweiler 2001）③ 手上只有〔待核〕数据 → 先争取答复时间窗去补数据，别用无据数字反锚 |

## 精确数纪律（含精度上限与对手分层）

- 锚定报价用精确非整数字（如 26.5K 而非「25-30K」），配一句依据陈述（「基于我看到的同岗位数据和我现在的 package 算的」）。依据：精确报价让对方让步更小、显得更有据（Mason et al. 2013）。
- **精度有上限，不是越细越好**：精度须匹配薪酬口径——月薪谈到 0.5K/1K 级即可，总包口径谈到万级；**禁止百元以下零头**（「26,485 元」式报价显得刻意）。对专家型对手（HRD / 谈判老手），过度精确会反噬——被解读为缺乏大局观（Loschelder et al. 2016 倒 U 效应，见 evidence-notes）；此时降一档精度（26.5K 而非 26.8K）并**必须**保留依据陈述——同一研究表明归因陈述能抵消反噬，这正是锚定卡强制绑定依据的原因。
- 窄区间只作为**让步预备位**保留在阶梯里（对方对精确数强反弹时退到窄区间），不是首发形态。窄区间设计有学术支撑（Ames & Mason 2015 bolstering range：下限抬至期望值的窄区间兼顾锚定与余地）——这与下条「下限 ≥ 满意层」的实战操作一致。
- 中文实战注意：报区间时 HR 默认取下限（practitioner 共识，见 cn-workplace-notes.md）——所以如果非要报区间，下限必须 ≥ 满意层；**在线表单必填期望薪资**的场景同此处理（详见 cn-workplace-notes.md HR 动作表首行）。

## 市场数据三选一标注（含卡面可引用性分层）

| 标注 | 判定 | Brief 内部校准 | 卡面可引用性 |
|---|---|---|---|
| 用户提供·亲历 | 自己的旧 offer / 自己拿过的报价 | 可用 | 可上卡直引 |
| 用户提供·他人实数 | 朋友 / 同事 / 同司同级的实数 | 可用（高可信校准） | **禁点名**——不得说「我朋友/你们家同级拿 X」（暴露他人 + 踩薪酬保密红线），只能匿名泛化为「我掌握的同岗位实际数据」 |
| 公开来源 | 用户给出链接或明确来源名 | 可用 | 可上卡带来源（「我看到 X 上同岗位…」） |
| 〔待核〕 | 用户「听说」「感觉」「大概」 | 保留槽位不作依据 | **禁用**——锚定卡不能建在〔待核〕数字上，宁可走「后报探底」分支 |

**报数先问依据**（与 SKILL.md probe-basis-first 同步）：用户主动报数先问「这个数怎么来的」再入表分类。中国市场无 Levels.fyi 等价的可靠公开数据源；不要替用户「查一个市场价」填槽。

## 可交换议题清单（package 视野）

base / 签字费（一次性，最容易批） / 绩效奖金比例与保底 / 期权与授予节奏 / 职级定级（影响后续一切涨幅） / 年假 / 远程与弹性 / 调薪机制（入职 6 个月 review 是弱 BATNA 场景的核心工具） / 培训与转岗窗口 / 到岗时间（对方的急迫是你的议题）。

谈薪 / 加薪场景 Brief 至少激活 2 个非 base 议题进阶梯，否则 rubric fatal #2 预警。

## 让步阶梯设计

- 每步「让什么 + 换什么」成对：白让训练对方继续压。
- 步幅递减（首步最大、越让越小），传递「接近极限」信号；末段可附非金钱附赠。递减节奏是从业者方法（Voss Ackerman，见 evidence-notes.md 标注层级），不当学术结论引用。
- 底线之下没有台阶：阶梯最后一步 = 底线本身 + 触线动作（转议题或体面收场）。
